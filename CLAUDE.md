## Next.js version warning

This is Next.js 16 — APIs and conventions may differ from training data. Read the relevant guide in `node_modules/next/dist/docs/` before writing Next-specific code and heed deprecation notices. The `nextjs-agent-rules` block in `AGENTS.md` is regenerated by `next dev`; leave it in place.

## Commands

- `npm run dev` — dev server on :3000 (Docker: `make shell` opens a shell in the `medasin-fe` container)
- `npm run lint` — ESLint (flat config, `eslint-config-next` core-web-vitals + typescript)
- `npm run build` — production build; also the type check. Run lint + build before considering work done.
- `npm test` — Playwright browser tests (run `npx playwright install chromium` once first)
- Single test file: `npm test -- src/features/auth/auth.browser.test.ts`
- Single test by name: `npm test -- src/features/habits/habits-page.browser.test.ts -g "<test title>"`

### How the tests work

Tests are `src/features/**/*.browser.test.ts` (see `playwright.config.ts`). Playwright starts its own `next dev` on `127.0.0.1:3107` with `NEXT_PUBLIC_API_URL=http://127.0.0.1:3107/api-test/v1`; each test mocks the backend via `page.route("**/api-test/v1/**", ...)` with in-memory fixtures. They never hit a real backend. Workers = 1, and `reuseExistingServer` is false, so a server already on port 3107 will block the run. Shared fixtures live in `src/test-utils/`.

## Architecture

- **Routing:** `src/app/(auth)` holds public auth pages (login, register, verify-email, forgot-password); `src/app/(app)` holds protected pages. Route `page.tsx` files are thin — they unwrap `params`/`searchParams` (Promises in Next 16) and render a page component from `src/features/<feature>/components/`.
- **Auth gating is client-side:** `src/app/(app)/layout.tsx` is a client component that calls `useRoleGate()` → `useCurrentUserQuery()` (`/auth/me`) and shows a skeleton until the user loads. It also wraps the shell in `FocusSessionProvider` and applies the user's font preference. Authentication is cookie-based (`withCredentials`), no tokens in JS.
- **API layer:** always use `axiosClient` from `@/lib/axios` (importing the index registers interceptors). `interceptors.ts` normalizes every failure into `ApiError` (`status`, `code`, `validationErrors`, `data`), transparently retries 401s after a single queued `POST /auth/refresh`, and redirects to `/login` with a toast when refresh fails. Public auth endpoints are exempt from refresh.
- **Proxy:** `next.config.ts` rewrites `/api/v1/*` and `/storage/*` to the backend origin (`API_ORIGIN`, or derived from `NEXT_PUBLIC_API_URL`), so cookies can be same-origin.
- **Feature module pattern** (`src/features/<feature>/`): `services/*-service.ts` (plain objects of axios calls that unwrap `response.data`, accept an `AbortSignal`), `queries/*-query.ts` (TanStack Query hooks plus a `xxxKeys` query-key factory — invalidate through these keys), `schemas/` (zod, used with react-hook-form), `type.ts`/`types.ts`, `components/`, `hooks/`. Many `store/` folders exist but are empty — there is no global state library; server state lives in React Query.
- **Query defaults** (`src/providers/query-provider.tsx`): `staleTime` 60s, query retry 1, no refetch on focus, no mutation retry.
- **Realtime:** `src/lib/reverb/client.ts` builds a Laravel Echo/Reverb client (returns `null` if `NEXT_PUBLIC_REVERB_*` env is missing), authorizing private channels through `axiosClient` at `/broadcasting/auth`. Used for plan reminder notifications (`src/features/plans/notifications/`), which also poll over HTTP every minute as fallback.
- **Subscriptions vs. plans:** `src/features/subscription/` is the product tier (Free/Focus/Clarity) and entitlement UI; `src/features/plans/` is the unrelated user-created calendar plans feature. Don't mix them. The backend is authoritative for limits; detect rejections with `isPlanLimitError()` (`ApiError.code === "PLAN_LIMIT_EXCEEDED"`) and `getPlanLimitMeta()`. Design notes live in `tasks/`.
- **UI:** shadcn (`base-vega` style, built on `@base-ui/react`, not Radix) primitives in `src/components/ui/`, Tailwind v4 (config in `src/app/globals.css`), lucide icons. Heavy client-only widgets (BlockNote note editor, FullCalendar, image crop) load via `next/dynamic`.
- `types/` holds Next-generated route types — don't edit; it is excluded from tsconfig and lint.

## Conventions

- Kebab-case filenames, PascalCase components/types, `use`-prefixed hooks, `@/*` alias for `src/`, two-space indentation, double quotes, semicolons.
- Conventional Commits (`feat(auth): ...`, `fix`, `refactor`, `docs`, `chore`).
- Backend-dependent features (Google sign-in, email codes, profile images, reminders) need backend config/migrations/queue workers; see README.md for the details before debugging "frontend" issues in those flows.
